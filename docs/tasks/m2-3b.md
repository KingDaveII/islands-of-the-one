## What this is

The holding is the Kindled's home island. After this task a player logs in, lands on the holding and can:
- walk around it;
- work the twisted trees or the stone outcrop: one active action, which keeps going while they look around and after they log out, up to the 48 h cap;
- take a station's basket into the store;
- move things between store and pack.

Skills gain XP from GAME DESIGN's curve.

Later tasks build on it:
- the Writ and the island's Name (Task 4);
- plots and their baskets' own cycles (Task 5);
- build mode (Task 6);
- sleep, the away card and toasts (Task 7).

Leave clean seams for them, named below, but don't build them.

### 3. Walking outside encounters (GAME DESIGN, 2026-10-16): a new sim module

Add `packages/sim/src/roam.ts`: deterministic integer movement for everywhere outside encounters. The holding is its first user; it's not part of the combat run.
- **Walk and run:**
  - The Kindled walks at `roam.walkFactor` × `player.moveSpeed` (0.7).
  - It breaks into a run on its own after `roam.runAfterMs` (1200) of moving without stopping or turning more than `roam.resetTurnDeg` (90).
  - It ramps up to full speed over `roam.rampMs` (400).
  - Stopping or a sharp turn drops it back to a walk.
  - A stick pushed less than `roam.walkStickMax` (0.6) always walks. The keyboard counts as a full push.
  - No run button.
- **No combat, no backpedal factor.** Facing follows the movement direction; standing still keeps the last facing.
- **Collision:** against the layout's solids, with the same `collideWalls` as rooms.
- **Tuning:** the keys go in `tuning.json` under `roam`, in the sim's integer forms.
- **Tests:** the same seed and inputs give the same hash, the walk-to-run timing, the reset on a stop and on a sharp turn, and the stick threshold.

**Positions on the holding are the client's.** M2 holdings are private and nothing of value depends on where you stand. The server checks that a station exists in the layout, not where the player is. Put the range check in one server function that returns true today, with a comment that visits (later) make it real.

**Animation:**
- `walk` by distance at `anim.walkCyclePx`, `run` at `anim.runCyclePx`;
- `run_start` and `run_stop` (awaiting art) when the run begins and ends;
- `idle` standing.

### 4. Stations and the active action (server)

The stations, in shared data (`stations.json`, or inside `holding.json`):

| station | kind | action | yields | cycle | skill | XP per cycle |
|---|---|---|---|---|---|---|
| `writ-post` | post | none: Use opens the inventory with the store pane | n/a | n/a | n/a | n/a |
| `twisted-trees` | trees | a dead branch | 1 `twisted-log` | 4 s | Woodcutting | 4 |
| `stone-outcrop` | outcrop | surface stone | 1 `black-stone` | 6 s | Mining | 6 |

A living branch, regrowth and the quarry's layers come later, with their items; note them in the PR, don't build them.

**One active action per Kindled.**
- A new table, `holding_activity`: the Kindled (primary key), station, `started_at`, `credited_cycles` and `last_seen_at`. Write it as an expand-only migration.
- Starting work at a station replaces any other action: settle first, then switch.
- Stopping settles, then clears the action.

**Settling** is how progress is computed. Nothing ticks in the background (CLAUDE.md), and the server computes on every holding request. In one transaction, with the activity row locked `FOR UPDATE`:
1. **The end:** `end = min(now, last_seen_at + 48 h)`. The 48 h offline cap goes in data, not code.
2. **Count:** completed cycles = `floor((end − started_at) / cycle) − credited_cycles`.
3. **Credit them:**
   - the yield into `basket:<station>` through `inventory.apply` (reason `gather`, in the same transaction via its `tx` option, ref `act:<kindled>:<started_at>:<credited>-<new total>`);
   - the XP into the skills table.
4. **Lost time:** if `end < now`, the time between `end` and `now` was beyond the cap. Restart the cycle clock at `now` (a fresh `started_at`, `credited_cycles` 0), so lost time is never paid later.
5. **Last seen:** set `last_seen_at = now`.

Online play keeps `last_seen_at` fresh, so the cap only bites away from the game. A Writ that's dark (Task 4) stops offline earning: put that in one function, `offlineAllowed(kindled)`, that returns true today.

**Baskets** have no limit in this task: what the 48 h rule produced waits there.
- **Take all** (Use on a station → Take all) moves the basket into the store through `POST /api/inventory/move`, or a server helper sharing its code, **moving only what fits**. GAME DESIGN, 2026-10-17: when a store stack is full, the rest stays in the basket and the line says "Store: twisted logs full."
- 3a's move refuses an over-limit set, so take-all computes what fits under the lock and moves that.

### 5. Skill XP (GAME DESIGN's curve)

- **Skills have no level cap.**
- **XP to go from level L to L + 1** = `round(40 + 12,300 × (1.08^L − 1.08))`. Level 2 is at 40 XP.
- **XP per action** is the action's base time in seconds. Basket cycles from plots, which come in Task 5, earn none.
- **Generate the table, don't compute it at runtime:** a generated `packages/shared/data/skills.json` holds the XP needed for each level, cumulative, from 1 to 200. Write a test that recomputes it from the formula with integer-exact checks.
- **Pin some values in the test:** level 2 at 40 XP; level 10 at about 47,000; level 20 at about 300,000. Pin the exact numbers your table gives.
- Beyond the table, compute the same formula in one shared function with a test at 200 and 250.
- **A `skill_xp` table:** (Kindled, skill, XP as bigint). It's written only in the settle transaction. XP is not an item, so it isn't in the item ledger.
- **The skills of M2:** Woodcutting, Mining, Farming. Farming has no station until Task 5.

### 6. The API (`packages/shared/src/api.ts`, guards and error codes)

- **`GET /api/holding`** settles, then answers:
  - the layout id;
  - per station, its basket counts;
  - the activity (station, `started_at`, cycle ms, the server's now);
  - each skill's XP, level, XP into the level and XP to the next.
- **`POST /api/holding/work`** `{ stationId }`: start or switch.
- **`POST /api/holding/stop`**.
- **`POST /api/holding/take`** `{ stationId }`: take all, what fits.

Every route:
- settles first;
- takes the Kindled from the session cookie only;
- refuses unknown fields and stations;
- answers the same shape as GET.

**The heartbeat:** while the holding scene is open, the client calls `GET /api/holding` every 30 s and after each interaction, so `last_seen_at` stays fresh and the counts stay true.

### 7. The client

**The holding scene** is a new Phaser scene on the world and UI cameras, as runs use them.
- After login, the start screen's main action is **HOLDING**. The M1 run stays as a secondary entry (it's still the combat test bed) until boats reach encounters.
- In the world:
  - the tile room;
  - the three props with shadows by the prop rule;
  - the Kindled walking by `roam`;
  - the interact prompt on the nearest station, with the existing prompt rules and range.

**The HUD** (placeholder panels; ART's kit comes later):
- **Bottom centre, the active-action chip:**
  - the station's placeholder icon (initials);
  - the skill name and level;
  - a progress ring for the current cycle, drawn from `started_at`, the cycle and the server's clock offset;
  - a thin XP bar to the next level;
  - empty when idle;
  - clicking it, or its pad binding, stops the action.
- **Bottom right, the pack button** with its fill (`12/20`). It opens the inventory with the store pane, since we're on the holding.
- **Top right, the gin purse.**
- **Over the station, a "+1"** as each cycle completes. It's predicted from the ring, render only; the counts come from the server.

**Interacting:**
- **The Writ post:** Use opens the inventory with the store. The Writ panel is Task 4.
- **A tree or the outcrop:** Use opens a small station panel showing:
  - the name;
  - "1 twisted log every 4 s";
  - the basket count;
  - "You: 1 log every 4 s" while working here;
  - the skill's level and XP to the next;
  - buttons **Work here** / **Stop** and **Take all**.

  After Take all, a one-line result ("Store: twisted logs full." when it applies) shows with the same blink-and-hold timing as the inventory's refusal line. Toasts proper are Task 7.
- **Controls** come from `controls.json`: interact is E, Cross or a tap; I or the Touchpad opens the inventory; Esc or Circle backs out. No hard-coded keys.
