# G1.5h: sort by the feet, and a backpedal that plays the run backwards

Read CLAUDE.md, `docs/design/sprites.md` (§8) and `docs/design/readability.md`, then `apps/client/src/render/characters.ts`, `chestSprites.ts`, `depth.ts`, `feet.ts` and `animState.ts`.

Work on the branch `g15h-sort-backpedal`, which already holds this file (`docs/tasks/g15h.md`). Merge the latest `main` into it first. Open one PR, "G1.5h: sort by the feet, backpedal", through the REST API (`gh pr create` is blocked).

## Why

These come from David's M1 playtest at B:

1. **The chest draws over the Kindled when it shouldn't.** Bodies are y-sorted by the sim's body centre: the Kindled's sits 5 sim px above its feet, and a Husk's sits its radius above its feet. The chest is sorted by its own base line. So the Kindled standing just in front of a chest still sorts behind it.
2. **The Kindled has no backwards run.** Aim and movement are separate, so the Kindled often runs away from where it faces, for example facing E while moving W. The run cycle then plays forwards and the legs stride the wrong way.

## Decisions (MAIN)

### 1. One sort key: the ground line

- Every y-sorted world sprite sorts by the line it stands on, in sim px:
  - the Kindled: `y + PLAYER_FEET`;
  - a Husk: `y + radius`, the same feet `feet.ts` already uses to place it;
  - the chest: its position, which is already its base;
  - anything else in the bodies layer: say what you did with it.
- Put it in one function next to `feet.ts`, for example `groundLine(kind, simY)`, and use it at every `setDepth(DEPTH.bodies + …)`.
- **Ties:** the same ground line keeps today's order, so the Kindled still draws over a Husk on the same line. Make the rule explicit and tested.
- This changes only the draw order, never positions.

### 2. Backpedal: the run played in reverse

While the Kindled runs, compare the movement direction with the facing, which comes from the aim:
- When the angle between them is **above 112.5°**, play the run cycle **backwards**: frame `n − 1 − f` for the distance-driven frame `f`. That means the movement falls in the three facings opposite the aim.
- Switch back to forwards **below 100°**. The hysteresis keeps a stick held near the boundary from flickering.
- Strafing, roughly 90°, keeps playing forwards.
- The facing stays the aim's, as now. Only the frame order flips.
- Take the movement direction from the same interpolated render positions the `StrideMeter` uses. Don't add a sim input.
- Keep it to the Kindled's `run`. The Nutshell's walk, and `walk` in general, stay as they are.
- This is the stopgap: if ART later draws a dedicated `run_back`, it replaces the reversed run under the same rule. Make the rule a small pure function, so swapping in an animation later is a one-line change.

## Don't

- Don't touch `packages/sim`, `tuning.json` or `rooms.json`; the goldens don't move. Making the chest solid and slowing the backpedal are sim changes that GAME DESIGN is deciding; they come in a later task.
- Don't change any art.
- Don't make visual calls. Put them under "Questions for ART".
