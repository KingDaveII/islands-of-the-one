# G1.5g: M1 at B, cleaned up: no procedural room or chest, no v1 sprite path, ready for the playtest

Start once ART's three asset PRs are merged: #58 (`tiles-cave`), #59 (`prop-chest`) and #60 (`husk-peeling`, `husk-nutshell`). Then every sprite sheet the game ships is v2 at B.

**First:** check that all three are on `main` (`packages/shared/assets/sprites/` holds `tiles-cave`, `prop-chest` and both Husks, all with `meta.version` `"2"`). If any is missing, stop and tell David. Then merge the latest `main` into this branch.

Read CLAUDE.md, `docs/design/sprites.md`, `docs/design/readability.md` and `docs/design/art-pipeline.md`.

Work on the branch `g15g-cleanup`, which already holds this file (`docs/tasks/g15g.md`). Open one PR, "G1.5g: M1 at B, cleaned up", through the REST API (`gh pr create` is blocked).

## Why

G1 swapped M1's art for B art one sheet at a time. To keep the game working in between, the engine carried fallbacks:
- the procedural room and doors (`drawRoom`, `drawDoors`);
- the procedural chest (`drawChest`);
- the whole v1 sprite path: sheets drawn at the legacy 2×, the whole-sheet clay swap, the time-based walk on v1, the light attack's wind-up stroke, and M1's hook offsets (`m1HookbladeOffset`).

Now every sheet is at B, so the fallbacks are dead code that tests keep alive. This task removes them and leaves one path. It is the last engine step before David's M1 playtest at B, which closes G1.

## Decisions (MAIN)

### 1. Remove the fallbacks

- **Room:** the procedural room and doors go. The room always draws from the tile sheet. `roomRenderer` and the `'procedural'` branch go too.
- **Chest:** `drawChest` goes, along with its blinking clasp and `chestRenderer`'s `'procedural'` branch. The engine keeps the chest's ground shadow (MAIN's call in #57).
- **Missing sheets:** a sheet that fails to load is an error like any other missing sprite sheet. Find out what the loader does today for a missing Kindled or Husk sheet and do the same; don't invent a new path.
- **Playtest hooks:** the overrides that only existed to stand in for missing art go:
  - `setTileSheet`, `setChestSheet`;
  - `window.__iot.useTileSheet`, `useChestSheet`.

  Keep the fixtures under `packages/shared/test/fixtures/`. The tests still use them by calling the pure functions directly.

### 2. Remove the v1 sprite-sheet path

v1 sprite sheets (`meta.version` `"1"`, drawn at 2) no longer exist in the game. Remove the code that only served them:
- the legacy 2× draw for sprite sheets, and `LEGACY_PIXEL_SCALE` where only sprite sheets use it;
- the whole-sheet clay swap: tones are always swapped under the mask;
- the time-based walk and run on v1 sheets: the Kindled's walk and run always play by distance (the Nutshell's walk stays time-based, as designed);
- the light attack's v1 wind-up stroke (`lightSlashMark`'s v1 branch);
- `m1HookbladeOffset`: a Kindled frame that needs a point always has one, and the sheet test guarantees it.

Then:
- The §6 sheet test **rejects** a v1 sprite sheet ("v1 sprite sheets are retired; build it through the pipeline"). It no longer checks v1 rules.
- `tools/placeholder-sheets.py` only made v1 sheets, so delete it and its mention in `sprites.md`.

**Keep the engine-sheet meta (`version`, `pixelScale`, `tinted`) and its defaults.** The controller glyphs are still a tinted engine sheet without meta.

If something else turns out to serve only v1, remove it too, and list it in the PR.

### 3. Audit: nothing in the world at M1's 2×

List every world drawing that isn't a v2 sheet: the engine's own shapes and effects, such as decals, pickups and drops, the slash arc, the thrust line, particles, poise bars, telegraph rings, the pad reticle and the Haul guide. Say for each whether it's drawn at B density, meaning 1 world px is 1 px of the shape. Wrong cases:
- a shape built from 2×2 blocks;
- a size doubled from M1's sim-px drawing.

Fix the mechanical cases: a drawing that is already designed at 1 px but scaled by 2. Anything whose look would change goes under "Questions for ART" instead. Put the audit table in the PR description.
